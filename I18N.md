## Quick start

```swift
import SeelWidget

SeelWidgetSDK.shared.configure(
    apiKey: "your_api_key",
    environment: .production,
    adminDomain: "your-store.myshopify.com"   // required to fetch translations
)
```

That `adminDomain` is the whole setup. The SDK fetches the merchant's copy for the device language and applies it; the UI follows.

Leave it out and the SDK still works — it just shows its built-in English.

---

## Where translations come from

The SDK merges two sources, the quote-level one winning:

| Source | When | Scope |
|---|---|---|
| `GET /v1/shopify/merchant-configs` → `merchants[0].i18n_config` | At `configure` (needs `adminDomain`) | All SDK copy |
| `POST /v1/ecommerce/quotes` → `extra_info.i18n` | With every quote | Wording specific to that quote |

Both carry the same shape:

```jsonc
{
  "lang": "fr-FR",
  "texts": [
    { "key": "Privacy Policy", "value": "Politique de confidentialité" },
    { "key": "Secure Your Purchase Now", "value": "Protégez votre achat" }
  ]
}
```

They are stored separately and merged on read, so a new quote never wipes out the merchant-level baseline.

**Neither request failing can blank the UI** — anything not found falls back to the English source string.

## Choosing the language

```swift
// Follow the device (default)
SeelWidgetSDK.shared.language = nil

// Or pin one
SeelWidgetSDK.shared.language = "fr-FR"

// What is actually in effect
print(SeelWidgetSDK.shared.resolvedLanguage)   // "fr-FR"
```

The device language is normalized to the tags the backend expects, matching the storefront scripts' `LANG_LIST`:

| Device reports | Normalized to | Why |
|---|---|---|
| `zh-Hans-CN` | `zh-CN` | Script subtag dropped |
| `zh-Hant-TW` | `zh-TW` | Traditional split by region |
| `zh-Hant-HK` | `zh-HK` | |
| `fr-CA` | `fr-FR` | Region unsupported; falls to the language's default region |
| `en-GB` | `en-US` | Same |
| `nn-NO` | `nb-NO` | Norwegian merged |
| Anything unknown | `en-US` | Fallback |

Setting `language` re-fetches the config and re-renders on-screen views — no component rebuilding, no repeated quote request.

## Lookup rules

**The key is the English source string.** Not a typo — the backend copy library is keyed by English text, the same convention the Shopify storefront scripts and the React Native SDK use. One set of backend copy serves all three platforms.

Lookup order:

```
quote-level translations  →  merchant-configs translations  →  built-in English
```

Copy the backend sends with the quote (`widget_title`, `display_widget_text`, `coverage_details_text`, `widget_disclaimer`) goes through **the same table**. It is English source text too, so it gets translated as well — exactly what the web does with `i18nConfigTextsJson[text] || text`.

## Placeholders and word order

Some strings carry `{{placeholders}}` the SDK fills in client-side:

| String | Placeholders |
|---|---|
| `{{title}} for {{price}}` | Coverage name, price |
| `Only {{price}} for Complete Peace of Mind` | Price |
| `Powered by {{seel}}` | Brand name |

**Word order comes from the template, not from concatenation.** A French translation can be written as:

```json
{ "key": "{{title}} for {{price}}", "value": "Pour {{price}}, ajoutez {{title}}" }
```

and renders as "Pour **$3.75 USD**, ajoutez **Worry-Free Purchase®**" — the price moved to the front, with the title and the price each keeping their own weight and size. Translations are free to **move placeholders anywhere**; they never have to follow English word order.

A placeholder with no value is left as-is (`{{price}}`), which makes a missing value obvious during integration.

## Caching and refresh

- Translations are **cached per language in `UserDefaults`**. On a cold start the UI renders the last known copy instead of flashing English while the request is in flight.
- A fresh response overwrites the cache.
- Switching language clears the current copy and re-fetches.
- On any change the SDK posts `SeelI18nDidChange`; widgets, banners and a presented modal rebuild their copy automatically.

To refresh your own UI alongside:

```swift
NotificationCenter.default.addObserver(
    forName: .SeelI18nDidChange, object: nil, queue: .main
) { _ in
    // your refresh logic
}
```

## Bring your own copy

If you already run your own translation pipeline, or need offline / test copy, inject it directly:

```swift
SeelI18nManager.shared.setTexts([
    "Privacy Policy": "Politique de confidentialité",
    "Secure Your Purchase Now": "Protégez votre achat",
])
```

Injected copy sits at the merchant-configs level and is still overridden by quote-level translations. `SeelI18nManager.shared.reset()` clears everything back to the built-in English.

## Parity with Web and React Native

| | Storefront scripts | React Native SDK | iOS SDK |
|---|---|---|---|
| Source | merchant-configs | Quote response | **Both** |
| Lookup key | English source | English source | English source |
| Fallback | `dict[text] \|\| text` | `dict[KeyValue.x] ?? 'English'` | Same |
| Placeholders | `{{...}}` client-side | Same | Same |

All three look up the same keys, so backend copy configured once works everywhere. iOS takes both sources because merchant-configs is available at launch and covers the whole UI, while the quote route can carry wording specific to a single order.

## Troubleshooting

**Still all English**
1. Check that `adminDomain` was supplied — without it nothing is fetched.
2. Run in `.development` and watch the console: `merchant-configs loaded => lang: fr-FR, texts: 42`. `texts: 0` means the backend has no copy for that language.
3. Print `SeelWidgetSDK.shared.resolvedLanguage` to confirm the normalized tag is the one you expected.

**Only some strings translated**
The backend copy library is missing those English source strings. Compare against the [string inventory](#string-inventory) and send the missing keys over — especially the iOS-only group.

**Odd punctuation in the rejection tooltip**
The copy library's source strings have no trailing `:` or `.`; the SDK appends them. Translations should **not** include trailing punctuation or you get it twice.

**A placeholder renders literally as `{{price}}`**
The placeholder name in the translation doesn't match. Names must be identical to the English source (`{{title}}` / `{{price}}` / `{{seel}}`).

**Setting `language` does nothing**
Make sure the call is on the main thread. Also, `language` only accepts tags it can normalize; anything unrecognized falls back to `en-US`.

## API cheat sheet

```swift
// Supply the shop domain at configure time; translations are fetched and applied
func configure(apiKey: String, environment: SeelEnvironment = .production, adminDomain: String? = nil)

// Refresh manually (or supply the domain later)
func loadMerchantConfigs(adminDomain: String? = nil,
                         completion: ((Result<MerchantConfigsResponse, NetworkError>) -> Void)? = nil)

// Language; nil follows the device
var language: String?
var resolvedLanguage: String
var adminDomain: String?

// Inject or clear copy yourself
SeelI18nManager.shared.setTexts(_ texts: [String: String])
SeelI18nManager.shared.reset()
SeelI18nManager.shared.isLoaded

// Change notification
Notification.Name.SeelI18nDidChange
```
